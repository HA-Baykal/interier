## Key Results — bugs found in audit (all fixed, listed for the final RU report)
1. **Stars pre_checkout_query missing on the PRIMARY webhook** (`src/lib/telegram/connection.ts`,
   the route `/api/auth/telegram/webhook` used by «Подключить» in the admin panel): webhook was
   registered with `allowed_updates: ["message","callback_query"]`, so Telegram would never
   deliver `pre_checkout_query` → Stars checkout would stall forever. Fixed (added
   `pre_checkout_query`), tests updated. (The earlier fix in bots/telegram.ts helpers was not the
   registration actually used.)
2. **TON on-chain verification was fragile** (`payments-ton.ts`):
   - address compared as raw strings → silently never matched when owner pasted friendly
     `UQ…` and TonAPI returned raw `0:…` (or vice versa) → paid users got nothing. Fixed with
     `sameTonAddress()` via `@ton/core` `Address.parse().equals()`.
   - amount read only as `{value}` object; plain-string amounts parsed to 0 → underpayment
     matched nothing. Added `transferNano()` (object or string, fail-closed 0).
   - `limit=50` → 100 (deep history on busy wallets).
   - rate-midflight bug: `expectedNanoFor` recomputed from the *current* `ton_per_rub`; an admin
     changing the rate between invoice and confirmation could refuse valid transfers or accept
     underpayments. Fixed: `Payment.expectedNano?` frozen at creation; fallback for old rows.
   - `verifyTonPayment` had no ownership check → a logged-in user could poll/verify arbitrary
     payment ids. Now takes `ownerUserId`; the route passes `user.id` and returns 404
     `not_found` for foreign/unknown ids.
3. **TON client UX** (`TonPayButton.tsx`): polled 36 s then died with no recourse though
   confirmations can arrive later, and printed raw wallet error text on modal cancel.
   Rewritten: create → send → poll 20×3 s → on timeout keep payment id and offer
   «Проверить ещё раз» (8 more polls); benign cancel/reject messages suppressed.
4. **MiniApp Stars UI**: `openInvoice` callback fired «Оплата получена» for every outcome;
   InvoiceClosed actually returns status paid/pending/cancelled/failed → now distinct messages
   (+ keys pay_stars_pending/cancelled), haptic on success; typing corrected to
   `(url, status)`.
5. **YooKassa webhook 500 on malformed body** → gateway infinite retry; now safe JSON.parse +
   `{ok:true}` ack (never credits).
6. **`isUnlimitedMode` fail-open for anonymous**: with `test_unlimited=1` (the default) a call
   without a user got unlimited; now admin-only (`user?.isAdmin === true`). (Root cause of the
   user's «+2 не уменьшались» stays: test_unlimited=1 + owner is admin + first gen is always
   trial.)
7. **Bonus «+1 за подписку» demo grants** (fixed in the previous round, still relevant):
   `/api/rewards/verify` (site) and bot `bonusClaim` now verify for real — Telegram
   `getChatMember` (bot must be channel admin, `telegram_channel_id` set) / VK `groups.isMember`
   (`vk_access_token`+`vk_group_id`). «Не подписан» → refusal + subscribe link; «нельзя
   проверить» → refusal with owner hint, never a silent grant. Web **Account page** also still
   had the disabled/stale «Проверка подписок ещё не подключена» card → rewired to the real
   claim endpoint with result message + «Подписаться и проверить ещё раз» link (new key
   rewards_subscribe_now).
8. **Web BuyButton** (ЮKassa): logged-out buyers got a generic payment error → now 401 redirects
   to /login.

# Interier — дизайн интерьера по фото

Загрузите фото комнаты (черновая отделка или текущий ремонт) — сервис переводит её
в реалистичный дизайн-проект в выбранном стиле. Первая генерация бесплатна, дальше —
пакеты услуг и бонусы за подписки/приглашения.

> ⚠️ **Этот репозиторий находится в режиме тестирования.** Оплата (платные подписки)
> **не подключена** — мы сначала доводим продукт, затем вы включаете платёжные функции.

## Что уже работает

- ✅ Веб-сайт (Next.js) с адаптивным дизайном и темизацией
- ✅ Загрузка фото комнаты (drag & drop / камера) — JPG, PNG, WebP до 20 МБ
- ✅ Выбор стиля и генерация (в демо-режиме — профессиональный цветокордраяд превью)
- ✅ 1 бесплатная пробная генерация (все стили сразу или один)
- ✅ Пакеты услуг (без оплаты, отображаются как «скоро»)
- ✅ Бонусы: +1 за Telegram-канал, +1 за VK-сообщество, +1 за каждого приглашённого друга
- ✅ Реферальные ссылки, личный кабинет, история генераций
- ✅ Админ-панель: пользователи, стили, пакеты, настройки, переключение ИИ-провайдера
- ✅ PWA: устанавливается на Android и iPhone (иконка на экране)
- ✅ Русский + английский языки (переключатель в шапке)

## Деплой

Хранилище реализовано как **двухрежимное**: если заданы переменные облачного
хранилища — работаем на Vercel (БД = Upstash Redis / Vercel KV одной JSON-документом,
фото = Vercel Blob); без них — локальный файл `data/app.json` + `data/uploads/`.

### Vercel (serverless)

**Подробно, по кнопкам панели и без PR/merge: [инструкция Vercel](docs/VERCEL-SETUP.md).**

1. В Storage подключите **Upstash Redis** и **Public Vercel Blob** к проекту.
2. Проверьте переменные **Preview**, а не только Production:
   `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` (или полная legacy-пара
   `KV_REST_API_URL` + `KV_REST_API_TOKEN`). Для Blob — `BLOB_STORE_ID` (современное
   подключение с управляемым OIDC) **или** прежний `BLOB_READ_WRITE_TOKEN`.
   При наличии `BLOB_STORE_ID` создавать новый секретный токен не нужно: SDK сам
   получает и обновляет временные учётные данные Vercel.
3. Задайте собственные `ADMIN_EMAIL` / `ADMIN_PASSWORD`, а не публичный тестовый пароль.
   Настройте GenAPI через `COMPATIBLE_*` либо сохраните ключ в админке после входа.
4. Выполните **Redeploy последнего коммита проверяемой ветки**. Для генерации задан
   лимит 300 секунд — проверьте Fluid Compute / доступный лимит Vercel Functions.
5. Проверьте `/api/admin/bootstrap`, затем в админке — «Проверить ИИ и хранилища»
   (`/api/admin/genstatus?probe=1`, только администратору).

Preview и Production автоматически разделены: `app:db` остаётся у Production,
Preview получает отдельный стабильный Redis-ключ и подкаталог Blob для своей ветки.
Аккаунты/настройки между ними не общие. Без Redis вход, регистрация и сохранение
настроек на Vercel останавливаются с понятной ошибкой; без Blob генерация не запускается.
Так приложение не обещает сохранить то, что исчезнет после запроса.

Локально без облачных переменных работают `data/app.json` и `data/uploads/`.
При read-only ФС доступен только временный режим; это не замена облачным хранилищам.
Ошибка **настроенного** Redis/Blob никогда не переключает приложение молча на локальную базу.

> Public Blob доступен по точному URL даже для работы, не опубликованной в галерее.
> Это не закрытое хранилище с проверкой владельца; не загружайте конфиденциальные фото.
> Тарифы и лимиты Redis, Blob, Vercel Functions и GenAPI проверяйте перед использованием.

### Render (бесплатный тариф) — рекомендация

1. Загрузите репозиторий в GitHub (рабочая ветка).
2. В [Render](https://render.com) → **New → Web Service** → подключите репозиторий.
3. **Build command**: `npm install && npm run build`
4. **Start command**: `npm start`
5. В **Environment** добавьте переменные (пример в `.env.example`):
   - `SESSION_SECRET` — длинная случайная строка
   - `DATABASE_PATH`=`./data/app.json`
   - `GENERATION_MODE`=`compatible`
   - `COMPATIBLE_PROVIDER`=`genapi`
   - `COMPATIBLE_BASE_URL`=`https://api.gen-api.ru`
   - `COMPATIBLE_API_KEY`=`<ваш ключ gen-api.ru>`
   - `COMPATIBLE_MODEL`=`gpt-image-2`
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD` (по умолчанию `admin@interier.ru` / `admin123`)
6. При желании добавьте **Persistent Disk** (несколько сотен МБ) в каталог `data/`.

## Админ-аккаунт (тестовый)

- Логин: `admin@interier.ru`
- Пароль: `admin123`

> Изменить можно через переменные окружения `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
> Админ создаётся автоматически при первом запуске **и восстанавливается сам**,
> если аккаунт пропал (например, база была очищена).

### Если не входит в админку

1. Откройте `/api/admin/bootstrap` — эндпоинт покажет диагностику **без паролей**:

   ```json
   {
     "storage": "redis",           // redis | file | memory
     "adminEmail": "admin@interier.ru",
     "credentialsFromEnv": false,  // заданы ли ADMIN_EMAIL / ADMIN_PASSWORD
     "configuredAccountExists": true,
     "adminCount": 1,
     "ephemeralStorage": false     // true = данные теряются при рестарте
   }
   ```

2. Что смотреть:
   - `"adminCount": 0` — админа нет. Отправьте `POST /api/admin/bootstrap`
     (без токена — так как админа ещё нет), он создаст аккаунт заново.
   - `"storage": "memory"` / `"ephemeralStorage": true` — **временное хранилище**
     (типично для Vercel без Redis/Blob). Список `missingEnvironment` покажет недостающие переменные. Подключите Upstash Redis
     (`UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`) или примонтируйте
     диск в `./data`, иначе любые аккаунты исчезнут при рестарте.
   - `"credentialsFromEnv": true`, но пароль не подходит — значит вход идёт по
     значениям из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, а не по `admin123`.

3. Пароль меняется просто: обновите `ADMIN_PASSWORD` в панели хостинга и
   перезапустите сервис — новое значение применится к существующему аккаунту.

4. Чтобы можно было починить вход, когда админ уже существует, задайте
   `ADMIN_SETUP_TOKEN=<секрет>` и вызовите
   `POST /api/admin/bootstrap` с заголовком `x-setup-token: <секрет>` — пароль админа будет
   переустановлен из переменных окружения.

> Кавычки и лишние пробелы в переменных (`ADMIN_PASSWORD="admin123"`) больше не
> ломают вход — они отбрасываются автоматически. Email нечувствителен к регистру.

## Подключение реальной ИИ-генерации (оплата из России)

Прямые зарубежные сервисы (Replicate, OpenAI, Together, fal.ai) **не принимают
российские карты**. Поэтому для России используем **путь №1 — российский
API-агрегатор** с оплатой в рублях. Коннектор поддерживает **два провайдера**
(переключаются в `Настройки` → «Агрегатор (путь №1)» → «Провайдер»):

| Провайдер | Base URL | Модель (пример) |
|-----------|----------|-----------------|
| **GenAPI** (по умолчанию) | `https://api.gen-api.ru` | `gpt-image-2`, `nano-banana-pro`, `nano-banana` |
| **provod.ai** (OpenAI-совместимый) | `https://api.provod.ai/v1` | `google/nano-banana-pro`, `openai/gpt-image-2` |

GenAPI — **нативный REST**: `POST /api/v1/networks/{model}` с фото как data-URI,
затем опрос `GET /api/v1/request/get/{request_id}` до `status: success`.
Если в модели осталось префикс-имя (`google/nano-banana`), коннектор автоматически
приводит его к GenAPI-формату (`nano-banana`).

Настройки задаются в админ-панели (`/admin` → Настройки → блок «Агрегатор»)
или в `.env.local`:

| Поле | Что вписать |
|------|-------------|
| COMPATIBLE_PROVIDER | `genapi` или `openai-compatible` |
| COMPATIBLE_BASE_URL | `https://api.gen-api.ru` (genapi) |
| COMPATIBLE_MODEL | `gpt-image-2` (лучше всего держит планировку) |
| COMPATIBLE_API_KEY | твой API-ключ с рублёвым балансом |

Промпт намеренно требует «не менять стены/окна/двери/планировку», менять только
интерьер. Логика в `src/lib/generation/provider.ts` и `src/lib/generation/edit-compatible.ts`.

Сохранение нового ключа автоматически включает `compatible`. Пробелы, кавычки и
CR/LF в ключе, URL и модели удаляются. Ключ — write-only: браузер не получает его
обратно, пустое поле при сохранении не стирает секрет. Старое сочетание «сохранённый
ключ + предзаполненный demo» исправляется автоматически; явный выбор демо в новой
админке сохраняется. Ошибки провайдера отображаются без секретов, не заменяются
демо-картинкой. При полном сбое возвращается внутренняя пробная попытка/кредит
(возврат оплаты у внешнего провайдера этим не гарантируется).

Также доступен legacy-режим `replicate` (коннектор `src/lib/generation/replicate.ts`).

## Галерея и приватность

- **Галерея** (`/gallery`) — публичная витрина работ. Все генерации пользователей
  **по умолчанию приватные** (видны только владельцу в «Истории»).
- Пользователь может **сам решить** выложить свой дизайн в общую галерею
  (кнопка «Выложить в галерею» в студии или личном кабинете) и в любой момент
  убрать его. Личность владельца в галерее не раскрывается.
- При первом запуске галерея наполняется примерами от админа (превью стилей).

## Структура

```
src/
  app/            # страницы + API-маршруты (Next.js App Router)
    api/          # auth, generate, generations, rewards, admin, uploads, lang
  components/     # клиентские компоненты (Studio, Account, Admin, AppShell...)
  lib/            # db (хранилище), auth, billing, config, i18n, generation
public/
  styles/         # превью стилей для лендинга
  icons/          # иконки PWA
data/             # база (app.json) и загруженные фото (не в git)
```

Данные прототипа хранятся одним JSON-документом: в Upstash Redis на Vercel,
в `data/app.json` локально. `src/lib/db.ts` использует атомарный compare-and-set
в Redis и очередь локальных мутаций, чтобы параллельные запросы не стирали
аккаунты и сессии друг друга. Повреждённый документ сохраняется, а не сбрасывается.
Для большого числа пользователей стоит перейти на нормализованную БД вместо
загрузки целого документа на каждый запрос.

### Общая модель сайта

Новые генерации в студии по умолчанию используют **GPT Image 2 Low**. В админке есть
отдельный блок «Модель для всех пользователей»: выберите вариант и нажмите
«Применить для всех». Модель, качество и разрешение сохраняются атомарно в Redis;
ключ не возвращается в браузер. Старые изображения не изменяются. Тестовая панель
остаётся изолированной и сама по себе не меняет общую модель.

### Защитный режим до подключения подтверждения аккаунтов

Неподтверждённые обычные аккаунты не могут запускать генерацию (проверка на сервере,
до загрузки фото и расхода). Администратор продолжает тестировать; безлимит больше
не распространяется на остальных пользователей. Произвольные Telegram/VK ID и старые
бонусы не являются подтверждением личности. Реферальное начисление отложено до проверки,
а симулированная «проверка подписки» отключена.

Доставка email-кодов пока не подключена. Подтверждение аккаунта работает через мессенджер:
Telegram — подписанный `initData`/подтверждение кодом в боте, VK и MAX — одноразовая ссылка
из бота (`/api/auth/link`) или привязка кодом `bind_…`. Регистрация на сайте создаёт
неподтверждённый аккаунт: чтобы он мог генерировать, привяжите его к боту
(аккаунт → «Привязать бота» → код в бот). До подключения email-кодов и лимитов/CAPTCHA
защиту Preview не снимать.


### Вход через Telegram

Добавлен подтверждённый вход и привязка существующего аккаунта через `@interier_home_bot`.
Нужна настройка webhook администратором и живая проверка — кнопки не активируются только
от ввода Telegram ID. Для защищённого Preview предусмотрен серверный Vercel Automation Bypass,
не отключающий прикладную проверку webhook. Инструкция: [docs/TELEGRAM-LOGIN.md](docs/TELEGRAM-LOGIN.md).

Бесплатные изображения ограничены общим скользящим лимитом (по умолчанию 10 / 24 часа),
а обычные пользователи — частотой запросов. Подтверждение Telegram не является паспортной
идентификацией; перед открытым запуском нужна дополнительная антифрод-настройка.

## Бот = приложение (Telegram, VK, MAX)

Бот `@interier_home_bot` — не «уведомлятор», а тот же продукт в мессенджере: один аккаунт,
один баланс, одна история, один список деталей со ссылками. Сайт, мини-приложение `/app`
и бот используют одно ядро (`src/lib/generation/pipeline.ts`), поэтому расхождений в
поведении и в тратах кредитов не бывает.

Что доступно в боте и в мини-приложении:

| Действие | Сайт | Бот / мини-приложение |
|---|---|---|
| Дизайн по фото комнаты | `/studio` | фото в чат → выбор стиля |
| Правка словами («замени только шторы») | панель под результатом | «✏️ Изменить деталь» |
| Где купить детали (Ozon / Яндекс Маркет / Лемана ПРО …) | хотспоты на фото или список | список + кнопки-ссылки |
| История, публикация в галерее | `/studio`, `/gallery` | «🖼 Мои дизайны» |
| Вход без пароля | кнопка «Telegram» | `initData` в мини-приложении |
| Админ-контроль | `/admin` | владелец = `admin_telegram_id`: `/status`, `/users`, `/gens`, `/broadcast`, `/setmode` |

Один вебхук на оба назначения: `/api/auth/telegram/webhook` принимает подтверждения входа
(`auth_…`) и сразу передаёт всё остальное движку ботов. Отдельного адреса для «приложения»
нет и настраивать его не нужно. Повторы `update_id` отсекаются, поэтому ретрай Telegram не
тратит кредит; в группах бот молчит, пока чат явно не привязан.

### Как проверять правки, не мержа PR

Работаем длинным PR: ветка `arena/…-interier` → `main`, PR открыт и **не** мержится,
пока правки не закончены. Каждый пуш в эту ветку обновляет тот же PR, поэтому ревью
не распадается на куски, а мержится потом одна кнопка.

1. **Что изменилось в каждом шаге** — PR → вкладка *Commits*: один коммит = один шаг,
   в сообщении описано, зачем он; *Files changed* показывает итог по всем шагам; на
   любой строке диффа можно оставить комментарий (я отвечу в этом же PR).
2. **Живой сайт на каждом пуше** — Vercel собирает Preview-деплой (ссылка в статусе
   коммита «Vercel — Deployed»). Открыть и смотреть интерфейс/админку можно сразу.
   Для Telegram/MAX-сообщений превью защищено (Vercel Authentication), поэтому там
   либо временно снять защиту для *Preview Deployment URLs* в Settings →
   Deployment Protection, либо добавить к адресам `?x-vercel-protection-bypass=<секрет>`
   (в `telegram_mini_app_url` тоже). Без этого мессенджер упрётся в «Log in to Vercel».
3. **Автоматический вердикт** — GitHub Actions (шаблон `ops/github-ci.yml`):
   `npm run typecheck` → `npm test` (155 тестов) → `npm run build` → `npm run selftest`
   на собранном сервере, то есть вся цепочка «генерация → детали и ссылки → правка
   словами → движок ботов → единый вебхук Telegram». Зелёно — значит шаг можно считать
   рабочим, красно — видно, на каком именно шаге.
4. **Локально, если хочется руками:**
   ```bash
   git fetch origin && git checkout arena/01a07656-interier && git pull
   npm ci && npm run typecheck && npm test
   npm run build && npm start            # в другой вкладке терминала
   npm run selftest                      # 73 проверки против localhost:3000
   ```

Мержить нужно один раз — когда шагов уже не осталось. Если сессия/агент оборвётся,
ничего не теряется: все коммиты лежат в ветке и видны в PR, и влиться может то же
состояние ветки, что и при последней зелёной проверке.

### Пошаговый запуск на Vercel (шаг за шагом, не больше одного за раз)

Общий принцип: переменные — в панели Vercel (никогда не в чат и не в репозиторий),
токены ботов и ключи ИИ — можно править и в `/admin`, но для Telegram-входа токен обязан
быть именно в окружении (из него выводится секрет вебхука).

**Шаг 1. Убедитесь, что текущий сайт живой.**
Откройте боевой адрес (Production) и добавьте `/api/admin/bootstrap` — должен быть JSON с
`storage`. Если нет: сначала `Redeploy` последней ветки в Vercel (Deployments → ⋯ →
Redeploy), затем повторите.

**Шаг 2. Проверьте переменные окружения (Production и Preview).**
`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `BLOB_STORE_ID`, `SESSION_SECRET`,
`ADMIN_EMAIL`, `ADMIN_PASSWORD`, `COMPATIBLE_API_KEY` (+ `COMPATIBLE_MODEL`,
`COMPATIBLE_BASE_URL`), `VERCEL_AUTOMATION_BYPASS_SECRET`.
Список и назначение: [docs/VERCEL-SETUP.md](docs/VERCEL-SETUP.md).

**Шаг 3. Добавьте три переменные бота в обеих средах** (Vercel → Settings → Environment
Variables → Production **и** Preview → после каждой — Redeploy):

```
TELEGRAM_BOT_TOKEN      # токен из @BotFather (никому его не показывайте)
TELEGRAM_BOT_USERNAME   # interier_home_bot — имя без @
AUTH_PUBLIC_URL         # https://ваш-постоянный-домен  (без / и без параметров)
```

**Шаг 4. Разрешите боту видеть фото.** В @BotFather: `/setprivacy` → `Disable`
(иначе бот не получит изображение в группе).

**Шаг 5. Узнайте свой числовой Telegram id.** Напишите `@userinfobot` — он ответит числом
(например `444999999`). Это не токен и не секрет, его можно копировать.

**Шаг 6. Впишите владельца и адрес.** `/admin` → блок «🤖 Боты и мини-приложения»:
`admin_telegram_id` = число из шага 5, `public_base_url` = `AUTH_PUBLIC_URL`,
`telegram_mini_app_url` = `https://домен/app`. Сохраните.
Ваш аккаунт теперь админ и в боте, и в мини-приложении.

**Шаг 7. Подключите бота.** В том же `/admin`: блок «Telegram: вход и приложение».
Кнопка **«Проверить webhook_info»** читает у Telegram `getWebhookInfo` и `getMe` и показывает,
кто сейчас владеет ботом: адрес вебхука, какой адрес ждёт эта версия, очередь недоставленных
сообщений, ошибки доставки и включено ли приложение в боте. Секреты не показываются.
Дальше **«Подключить бота к этой версии»** — регистрирует вебхук с секретом.
Кнопка **«Применить профиль бота»** отправляет в Telegram имя (`telegram_name` из «Боты»,
`setMyName`), описание и короткое описание (RU и EN), список команд и кнопку-меню
«Открыть Interier» → `/app`; вебхук при этом не трогается.
Если Vercel ругается на защищённый Preview — создайте *Protection Bypass for Automation*
(`VERCEL_AUTOMATION_BYPASS_SECRET`) и сделайте Redeploy; адрес вебхука подставится сам.

> **Бот отвечает как старая версия** («этот бот подтверждает вход»). У бота один вебхук, и
> сообщения обрабатывает тот деплой, который зарегистрировал его последним. Нажмите
> «Проверить webhook_info»: если адрес ведёт на Preview (`…-git-main-….vercel.app`) или на
> другой домен — поставьте флажок «переключить бота на эту версию» и нажмите «Подключить»,
> затем «Применить профиль бота». Чтобы адрес не уезжал при каждом деплое, задайте
> `AUTH_PUBLIC_URL` (прод-домен) и `public_base_url`. Проверить то же самое из консоли:
> `npm run doctor -- --base https://ваш-домен --admin почта:пароль`.

**Шаг 8. Проверьте бота руками.** В Telegram: `/start` → меню → «🎨 Новый дизайн» → пришлите
фото комнаты → дождитесь результата → «🛒 Где купить детали». Затем «✏️ Изменить деталь» и
напишите своими словами, что менять. Один ответ с кнопками магазинов = всё работает.

**Шаг 9. Проверьте вход с сайта.** Откройте `/login` → «Telegram»: сайт покажет код, бот —
кнопку «Подтвердить». После подтверждения браузер получает сессию того же аккаунта, что и
бот. Для аккаунта, уже зарегистрированного паролем: `/account` → «Привязать бота» → `bind_…`
в чат — аккаунт считается подтверждённым и может генерировать.

**Шаг 10. Настройте магазины.** `/admin` → «Список покупок»: какие маркетплейсы включены и в
каком порядке, режим по умолчанию (хотспоты/список), партнёрские метки в
`shopping_extra_params` (`utm_source=…&partner_id=…`), показывать ли список в публичной
галерее (`shopping_public_links`), модель-визор для координат (`vision_*`).
Без мультимодальной модели ссылки всё равно выдаются — списком, без точек на фото.

**Шаг 11. VK — вторым, не трогая Avito.** Сообщество «Вектор комфорта» → Управление →
Работа с API → «Ключи доступа»: новый ключ с правами `messages`, `photos`,
`groups` (существующие ключи и Callback API Avito не удаляйте и не меняйте). В `/admin` →
«Боты»: `vk_access_token`, `vk_group_id`, `vk_confirmation_token`, `vk_callback_secret`.
Вебхук VK — отдельный адрес `/api/bots/vk/webhook`, он не пересекается с Callback API
сообщества. Дальше: «подключить VK» → проверка `groups.getById` → те же кнопки в диалоге.

**Шаг 12. MAX — третьим.** business.max.ru → ваш чат-бот → «Расширенные настройки» → токен;
`max_bot_token` в `/admin`. API — `platform-api2.max.ru` (старый хост остаётся запасным),
вебхук — `/api/bots/max/webhook`, HTTPS строго 443. Логика, кнопки и цены — те же.

**Шаг 13. Перед публичным запуском.** В `/admin` → «Настройки»: `test_unlimited` → выкл
(иначе кредиты не тратятся), `daily_free_image_limit` → сколько изображений можно всем
за 24 часа, `free_credits` → сколько кредитов выдавать, режим `compatible`, качество
(`low` дешевле всего: ≈2.50 ₽ за 1024²; `medium` ≈15 ₽; `high` ≈55 ₽ — выбор за вами,
«Применить для всех» меняет глобально). В «Ботах» выключите симулятор
(`bots_simulator=0`). Прогоните `npm run doctor -- --base https://ваш-домен` и
`npm run selftest -- --base https://ваш-домен` — оба должны быть без ошибок.

> Хостинг без постоянного HTTPS (локально, в Preview-ветке): вместо вебхуков запустите
> `npm run bots:poll` — тот же движок через long-polling. На Vercel фоновых процессов нет,
> поэтому для ботов включите `bots_inline_generation=1` (генерация заверляется внутри
> запроса вебхука, лимит функции 300 с).

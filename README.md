# Interier — дизайн интерьера по фото

Загрузите фото комнаты (черновая отделка или текущий ремонт) — сервис переводит её
в реалистичный дизайн-проект в выбранном стиле. Первая генерация бесплатна, дальше —
пакеты услуг и бонусы за подписки/приглашения.

> ⚠️ **Этот репозиторий находится в режиме тестирования.** Оплата (платные подписки)
> **не подключена** — мы сначала доводим продукт, затем вы включаете платёжные функции.

## Что уже работает

- ✅ Веб-сайт (Next.js) с адаптивным дизайном и темизацией
- ✅ Загрузка фото комнаты (drag & drop / камера) — JPG, PNG, WebP до 20 МБ
- ✅ Выбор стиля и генерация (в демо-режиме — профессиональный цветокордраяд превью)
- ✅ 1 бесплатная пробная генерация (все стили сразу или один)
- ✅ Пакеты услуг (без оплаты, отображаются как «скоро»)
- ✅ Бонусы: +1 за Telegram-канал, +1 за VK-сообщество, +1 за каждого приглашённого друга
- ✅ Реферальные ссылки, личный кабинет, история генераций
- ✅ Админ-панель: пользователи, стили, пакеты, настройки, переключение ИИ-провайдера
- ✅ **Боты-приложения в Telegram, VK и MAX** — полный функционал сайта из мессенджера
  (генерация, история, правки, баланс, админка), плюс мини-приложение `/app`
- ✅ **Список деталей готового дизайна со ссылками в магазины** — Ozon, Яндекс Маркет,
  Леруа Мерлен (Lemana Pro), Wildberries, Hoff, Петрович: хотспоты на фото или список
- ✅ **Правка дизайна словом** — «замени только шторы»: меняется только то, что просили,
  и на эти же шторы приходят ссылки магазина
- ✅ PWA: устанавливается на Android и iPhone (иконка на экране)
- ✅ Русский + английский языки (переключатель в шапке)

## Деплой

Хранилище реализовано как **двухрежимное**: если заданы переменные облачного
хранилища — работаем на Vercel (БД = Upstash Redis / Vercel KV одной JSON-документом,
фото = Vercel Blob); без них — локальный файл `data/app.json` + `data/uploads/`.

### Vercel (serverless)

1. Импортируйте репозиторий в Vercel (production-ветка — та, где лежит сайт).
2. Подключите два хранилища в панели Vercel:
   - **KV / Redis** (Upstash Redis или Vercel KV) — для базы.
   - **Blob** — для фото.
   Vercel сам подставит переменные (`UPSTASH_REDIS_REST_URL` / `..._TOKEN`,
   `BLOB_READ_WRITE_TOKEN`).
3. В **Environment Variables** добавьте приложения:
   - `GENERATION_MODE`=`compatible`
   - `COMPATIBLE_PROVIDER`=`genapi`
   - `COMPATIBLE_BASE_URL`=`https://api.gen-api.ru`
   - `COMPATIBLE_API_KEY`=`<ваш ключ gen-api.ru>`
   - `COMPATIBLE_MODEL`=`gpt-image-2`
   - `SESSION_SECRET`=длинная случайная строка
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD` (по умолчанию `admin@interier.ru` / `admin123`)
4. Deploy. `npm run build` + runtime `next start` выполняются автоматически.

> На бесплатном тарифе Vercel лимиты KV/Blob ограничены — для небольшого числа
> пользователей теста хватает. Если упрётесь в лимиты, добавьте платный план или
> вынесите данные на отдельный постоянный хостинг.

### Render (бесплатный тариф) — рекомендация

1. Загрузите репозиторий в GitHub (рабочая ветка).
2. В [Render](https://render.com) → **New → Web Service** → подключите репозиторий.
3. **Build command**: `npm install && npm run build`
4. **Start command**: `npm start`
5. В **Environment** добавьте переменные (пример в `.env.example`):
   - `SESSION_SECRET` — длинная случайная строка
   - `DATABASE_PATH`=`./data/app.json`
   - `GENERATION_MODE`=`compatible`
   - `COMPATIBLE_PROVIDER`=`genapi`
   - `COMPATIBLE_BASE_URL`=`https://api.gen-api.ru`
   - `COMPATIBLE_API_KEY`=`<ваш ключ gen-api.ru>`
   - `COMPATIBLE_MODEL`=`gpt-image-2`
   - `ADMIN_EMAIL` / `ADMIN_PASSWORD` (по умолчанию `admin@interier.ru` / `admin123`)
6. При желании добавьте **Persistent Disk** (несколько сотен МБ) в каталог `data/`.

### VPS (Hetzner и т.п.)

git clone https://github.com/HA-Baykal/interier.git && cd interier

# настройте .env (или экспортируйте переменные)

## Админ-аккаунт (тестовый)

- Логин: `admin@interier.ru`
- Пароль: `admin123`

> Изменить можно через переменные окружения `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
> Админ создаётся автоматически при первом запуске **и восстанавливается сам**,
> если аккаунт пропал (например, база была очищена).

### Если не входит в админку

1. Откройте `/api/admin/bootstrap` — эндпоинт покажет диагностику **без паролей**:

   ```json
   {
     "storage": "redis",           // redis | file | memory
     "adminEmail": "admin@interier.ru",
     "credentialsFromEnv": false,  // заданы ли ADMIN_EMAIL / ADMIN_PASSWORD
     "configuredAccountExists": true,
     "adminCount": 1,
     "ephemeralStorage": false     // true = данные теряются при рестарте
   }
   ```

2. Что смотреть:
   - `"adminCount": 0` — админа нет. Отправьте `POST /api/admin/bootstrap`
     (без токена — так как админа ещё нет), он создаст аккаунт заново.
   - `"storage": "memory"` / `"ephemeralStorage": true` — **файловая система
     только для чтения** (типично для Vercel). Подключите Upstash Redis
     (`UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`) или примонтируйте
     диск в `./data`, иначе любые аккаунты исчезнут при рестарте.
   - `"credentialsFromEnv": true`, но пароль не подходит — значит вход идёт по
     значениям из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, а не по `admin123`.

3. Пароль меняется просто: обновите `ADMIN_PASSWORD` в панели хостинга и
   перезапустите сервис — новое значение применится к существующему аккаунту.

4. Чтобы можно было починить вход, когда админ уже существует, задайте
   `ADMIN_SETUP_TOKEN=<секрет>` и вызовите
   `POST /api/admin/bootstrap?token=<секрет>` — пароль админа будет
   переустановлен из переменных окружения.

> Кавычки и лишние пробелы в переменных (`ADMIN_PASSWORD="admin123"`) больше не
> ломают вход — они отбрасываются автоматически. Email нечувствителен к регистру.

## Подключение реальной ИИ-генерации (оплата из России)

Прямые зарубежные сервисы (Replicate, OpenAI, Together, fal.ai) **не принимают
российские карты**. Поэтому для России используем **путь №1 — российский
API-агрегатор** с оплатой в рублях. Коннектор поддерживает **два провайдера**
(переключаются в `Настройки` → «Агрегатор (путь №1)» → «Провайдер»):

| Провайдер | Base URL | Модель (пример) |
|-----------|----------|-----------------|
| **GenAPI** (по умолчанию) | `https://api.gen-api.ru` | `gpt-image-2`, `nano-banana-pro`, `nano-banana` |
| **provod.ai** (OpenAI-совместимый) | `https://api.provod.ai/v1` | `google/nano-banana-pro`, `openai/gpt-image-2` |

GenAPI — **нативный REST**: `POST /api/v1/networks/{model}` с фото как data-URI,
затем опрос `GET /api/v1/request/get/{request_id}` до `status: success`.
Если в модели осталось префикс-имя (`google/nano-banana`), коннектор автоматически
приводит его к GenAPI-формату (`nano-banana`).

Настройки задаются в админ-панели (`/admin` → Настройки → блок «Агрегатор»)
или в `.env.local`:

| Поле | Что вписать |
|------|-------------|
| COMPATIBLE_PROVIDER | `genapi` или `openai-compatible` |
| COMPATIBLE_BASE_URL | `https://api.gen-api.ru` (genapi) |
| COMPATIBLE_MODEL | `gpt-image-2` (лучше всего держит планировку) |
| COMPATIBLE_API_KEY | твой API-ключ с рублёвым балансом |

Промпт намеренно требует «не менять стены/окна/двери/планировку», менять только
интерьер. Логика в `src/lib/generation/provider.ts` и `src/lib/generation/edit-compatible.ts`.

Также доступен legacy-режим `replicate` (коннектор `src/lib/generation/replicate.ts`).

## Боты и мини-приложения (Telegram / VK / MAX)

Один движок диалога — три мессенджера. Вся логика живёт в
`src/lib/bots/engine.ts`; `telegram.ts`, `vk.ts`, `max.ts` — тонкие адаптеры,
которые только переводят входящие/исходящие сообщения платформы в нейтральные
`BotInbound` / `BotOutbound`. Поэтому «/start», выбор стиля, генерация, список
покупок и правки работают одинаково везде, и любое изменение достаточно сделать
один раз.

```
фото комнаты → стиль → дизайн-проект
                          ↓
        🛒 список деталей: диван, шторы, торшер… + ссылки
                          Ozon / Яндекс Маркет / Леруа / WB
                          ↓
        «замени только шторы» → новый дизайн + ссылки на эти шторы
```

### Что умеет бот

| Команда / кнопка | Действие |
|------------------|----------|
| `/start`, `/menu` | приветствие + меню |
| 🎨 Новый дизайн | прислать фото → выбрать стиль → генерация (одна или все стили) |
| ✏️ Изменить деталь / текст словами | правка последнего дизайна: меняется **только** названное |
| 🖼 Мои дизайны | история; 👁 открыть, ✏️ править, 🛒 список покупок, 📤 в галерею |
| ⚡ Генерации: N / 🎁 Бонусы / 👥 Пригласить | кредиты, подписки, реферальная ссылка |
| 📱 Открыть приложение | мини-приложение `/app` прямо в мессенджере |
| `/link` | разовая ссылка `…/app?link=…` — вход в веб-версию без пароля |
| `/lang` | RU ⇄ EN для всех сообщений бота |
| `/admin` | только для владельца: статус, юзеры, генерации, рассылка, режимы |

Дизайны, кредиты и история **те же самые**, что на сайте: бот — это не отдельный
сервис, а второй интерфейс к той же базе.

### Подключение за 5 шагов

1. **Telegram**: `@BotFather` → `/newbot` → скопировать токен → `/setprivacy` → `Disable`
   (иначе бот не увидит фото в чатах). Вести диалог в личке — приватность не мешает.
2. Заполнить админку: `/admin` → блок «🤖 Боты и мини-приложения» → `telegram_bot_token`,
   `telegram_bot_username`, `public_base_url` (публичный HTTPS-адрес сервиса),
   `admin_telegram_id` — **ваш числовой id** (узнать: `@userinfobot`).
3. Нажать **«Подключить вебхуки»** (`POST /api/admin/bots/setup`) — эндпоинт сам
   вызовет `setWebhook` с секретом и поставит меню-кнопку на `${public_base_url}/app`.
   В BotFather дополнительно: Bot Settings → Menu Button → тот же `/app` URL
   (или `/setmenubutton`, если правите вручную).
4. **Ваш аккаунт = админ.** Совпал `admin_telegram_id` с id первого сообщения —
   пользователь получает `isAdmin: true`: кнопка ⚙️ в меню бота, вкладки
   «Боты»/«Шопинг» в мини-приложении и доступ к `/admin`.
5. **VK**: токен сообщества (`VK_ACCESS_TOKEN`, `VK_GROUP_ID`) → «Подключить вебхуки»
   ( Callback API: подтверждение эхом шлётся `VK_CONFIRMATION_TOKEN`).
   **MAX**: токен из `business.max.ru → self → Чат-боты → Расширенные настройки`
   (`MAX_BOT_TOKEN`); подписка создаётся на `POST /subscriptions` тем же setup-эндпоинтом.

> Проверить всё можно **не подключая мессенджеры**: админка → «🧪 Симулятор диалога»
> (или `POST /api/bots/simulator`, если включён `BOTS_SIMULATOR=1`) прогоняет
> сообщение через боевой движок и показывает ответ с кнопками.

### Если публичного HTTPS нет (dev, обычный HTTP, непроверенный бот MAX)

Вебхуки — основной транспорт, но он требует HTTPS. Тогда запускайте воркер
long-polling (он дергает `POST /api/bots/poll`, а тот забирает апдейты у Telegram и MAX):

```bash
BOT_BASE_URL=https://interier.example.com BOT_POLL_SECRET=<из админки> npm run bots:poll
# или один цикл по cron:  npm run bots:poll -- --once
```

VK всегда использует Callback API (long polling для ботов сообщества недоступен).
MAX во время активной подписки long-polling отключает — это нормально: setup сам
переключает транспорт.

### Мини-приложение `/app`

`src/app/app/page.tsx` + `src/components/MiniApp.tsx`: вкладки **Создать / История /
Магазин / Профиль** в родном для мессенджера окне (без шапки сайта, с кнопкой «назад»
Telegram, тактильной вибрацией на готовую генерацию).

Вход без пароля:
* **Telegram** — подпись `initData` проверяется на сервере (`HMAC-SHA256` на ключе
  `WebAppData`+токен, с проверкой свежести `auth_date`) → создаётся/находится аккаунт → сессия.
* **VK / MAX** — бот выдаёт разовую ссылку `?link=<токен>` (TTL `bots_link_ttl_min`),
  она обменивается на сессию ровно один раз.
* есть и обычный вход по email — приложение работает и в браузере.

## Список деталей интерьера → где купить

После генерации модель-визор (`src/lib/generation/vision.ts`) размечает картинку:
`{название, категория, цвет, материал, координаты}`. Для каждой детали собирается
поисковый запрос («бежевые льняные шторы для гостиной») и ссылки на те магазины,
где категория действительно продаётся (ламели не поедут на Wildberries за обоями, а
ламинат — на Ozon за текстилем).

* **Хотспоты** — точки на фото, по наведению всплывает карточка с названием и
  ссылками. Включаются только если координаты есть.
* **Список** — если хотспоты неуместны (картинка мелкая, координат нет), интерфейс
  сам переключается на список «деталь → магазины»; там же кнопка «Обновить подбор»
  и «➕ Отметить деталь» — клик по фото, название, готовые ссылки.
* Настройки: админка → «🛒 Список деталей и магазины» (магазины и приоритет,
  максимум позиций, режим по умолчанию, партнёрские `utm`-метки, показ в галерее,
  модель визора).

API: `GET/POST/DELETE /api/generations/[id]/items` — чтение, `refresh`/ручная
деталь, удаление. Список хранится прямо в генерации (`Generation.shopping`),
поэтому переиспользуется и в вебе, и в боте, и в мини-приложении.

## Правка дизайнов текстом

`POST /api/generations/[id]/edit {instruction}`:
`parseInstruction()` находит категории по словам пользователя и учёту отрицаний
(«меня устраивает цвет штор, замени **только** шторы» → цель = шторы, всё
остальное запрещено менять), промпт фиксирует стены/пол/потолок/окна/двери/камеру,
на вход подаётся **результат** предыдущей генерации, а в ответ возвращаются только
изменённые детали (`changed: true`) со своими ссылками. Цепочку правок видно в
истории (у каждой — «предыдущий» дизайн и текст инструкции).

## Галерея и приватность

- **Галерея** (`/gallery`) — публичная витрина работ. Все генерации пользователей
  **по умолчанию приватные** (видны только владельцу в «Истории»).
- Пользователь может **сам решить** выложить свой дизайн в общую галерею
  (кнопка «Выложить в галерею» в студии или личном кабинете) и в любой момент
  убрать его. Личность владельца в галерее не раскрывается.
- При первом запуске галерея наполняется примерами от админа (превью стилей).

## Структура

```
src/
  app/            # страницы + API-маршруты (Next.js App Router)
    api/          # auth, generate, generations, items, marketplaces, rewards, admin, uploads, lang
    api/bots/     # /telegram/webhook /vk/webhook /max/webhook /poll /simulator
    app/          # мини-приложение для мессенджеров (/app)
  components/     # клиентские компоненты (Studio, DesignItems, MiniApp, Account, Admin, AdminBots…)
  lib/            # db (хранилище), auth, billing, config, i18n
    generation/   # промпты, провайдеры, визор деталей, конвейер генерации/правок
    bots/         # engine.ts (общая логика) + telegram.ts / vk.ts / max.ts + store/setup/poller
    marketplaces.ts shopping.ts   # каталог магазинов и сборка списка покупок
scripts/
  bots-poller.mjs # long-polling воркер (когда нет публичного HTTPS)
  selftest.mjs    # сквозная проверка: генерация → детали → правка → боты
public/
  styles/         # превью стилей для лендинга
  icons/          # иконки PWA
data/             # база (app.json) и загруженные фото (не в git)
```

Хранилище пока на JSON-файле (`data/app.json`) — это удобно для прототипа.
Интерфейс изолирован в `src/lib/db.ts`, поэтому позже легко заменить на
PostgreSQL / SQLite / Prisma без переписывания бизнес-логики.

## Быстрая проверка всей цепочки

```bash
npm run build && npm run start      # или npm run dev
npm run selftest                    # ↑ в другом терминале, BASE по умолчанию :3000
npm run selftest -- --base https://interier.example.com
```

`scripts/selftest.mjs` регистрирует временный аккаунт, генерирует дизайн, требует
список деталей со ссылками, добавляет/удаляет ручную деталь, делает правку
«замени только шторы», проверяет историю, галерею, админские эндпоинты и движок
ботов в трёх мессенджерах. Ничего не отправляет пользователям и не трогает
реальные API мессенджеров.

# Оплата TON и Telegram Stars: полные настройки

Гайд по подключению и проверке двух «встроенных» способов оплаты пакетов
генераций. Все поля уже есть в админ-панели: **/admin → Настройки → «Приём
платежей (ЮKassa)»** (блок с TON и Stars внизу) и **/admin → Боты**.

Коротко: **Stars ничего подключать не нужно** (кроме работающего бота и
Mini App), а для **TON нужен только ключ TonAPI** — адрес кошелька вы уже
вписали (`ton_address`). Ниже — откуда взять ключ, что куда вписать и как
устроена проверка каждого платежа.

---

## 1. Telegram Stars (звёзды) — настройки

| Поле в админке | Значение | По умолчанию |
| --- | --- | --- |
| `⭐ Звёзд за 1 ₽ (курс)` | курс пересчёта рублёвой цены в звёзды | `1` (490 ₽ = 490 ⭐) |
| env (необязательно) | — | — |

Отдельных «ключей Stars» **не существует**: оплата идёт через вашего же бота
и Mini App. Обязательные условия:

1. Подключён бот Telegram (`telegram_bot_token`) и настроен вебхук
   (админка → **Боты** → «Подключить», адрес `…/api/bots/telegram/webhook`).
2. Покупатель открывает Mini App **внутри Telegram** — вне Telegram кнопка
   «⭐ Звёздами» показывает «Звёзды доступны только внутри Telegram».
3. Курс подбирайте под рынок звёзд (см. п. «Курс» ниже).

### Как происходит покупка и проверка за звёзды

```
Mini App ──"Купить за ⭐"──▶ POST /api/payments/stars/create
                                  │  createInvoiceLink(title, payload="stars:<payId>",
                                  │                     currency=XTR, prices=[{amount}])
                                  ▼
        Telegram показывает нативный чек «Оплатить N звёзд»
                                  │
       Telegram ──pre_checkout_query──▶ наш вебхук (обязательно ответить ≤10 c)
                                  │      answerPreCheckoutQuery(ok=true)
                                  ▼
     Пользователь подтверждает оплату → Telegram списывает звёзды
                                  │
       Telegram ──message.successful_payment──▶ наш вебхук
                                  │      invoice_payload = "stars:<payId>"
                                  ▼
   fulfillStarsPayment(): помечает платёж paid и начисляет кредиты пакета
   (идемпотентно: повторная доставка апдейта не задваивает начисление)
```

То есть **«проверка» здесь — это сам Telegram**: деньги списывает и
подтверждает он, а бот получает защищённый апдейт `successful_payment`
(подписанный через вебхук секретом `secret_token`), в котором лежит ваш
`invoice_payload` с внутренним id платежа. Сервер начисляет пакет только
после этого события и ровно один раз.

Важные детали реализации (уже исправлено в коде):

- Вебхук бота принимает `pre_checkout_query`: он добавлен в `allowed_updates`
  при установке вебхука и в long-polling — без этого Telegram не доставил бы
  запрос и чек «завис» бы на подтверждении.
- Обработка платежей вынесена в общий обработчик и работает и на вебхуке, и
  в режиме `npm run bots:poll`.

Официальная документация:
- Анонс Stars: https://telegram.org/blog/telegram-stars
- Детальное руководство по платежам звёздами:
  https://core.telegram.org/bots/payments-stars
- Bot API: `createInvoiceLink`, `answerPreCheckoutQuery`, `successful_payment`:
  https://core.telegram.org/bots/api
- Вывод заработанных звёзд: баланс бота в **@BotFather** → «Withdraw» (через
  Fragment), https://fragment.com — условия и комиссии там же.

> Возврат звёзд покупателю (если понадобится) делается вручную методом
> `refundStarPayment` по `telegram_payment_charge_id` из платёжной записи —
> автоматический возврат в приложении не предусмотрен.

## 2. TON — где взять ключ и что вписать

| Поле в админке | Что вписать |
| --- | --- |
| `💎 TON: адрес-получатель` | ваш кошелёк `UQ…` / `0Q…` — **уже вписан** |
| `TON API-ключ (tonapi.io)` | ключ из TonConsole (см. ниже) — сервер им проверяет перевод |
| `TON API-адрес` | `https://tonapi.io` (по умолчанию; менять не нужно) |
| `💎 TON за 1 ₽ (курс)` | сколько TON стоит 1 ₽ цены пакета (см. «Курс») |

### Где получить TON API-ключ (официально)

Код проверяет переводы через **TonAPI** (tonapi.io) — это API от команды
TON (Tonkeeper/TonConsole). Ключ выдаётся там же:

1. Откройте https://tonconsole.com (страница проекта TonAPI —
   https://tonconsole.com/tonapi) и войдите через **Telegram**.
2. Раздел **TonAPI → API keys** → **Create API key**.
3. Скопируйте ключ и вставьте его в админке в поле
   **«TON API-ключ (tonapi.io)»** (поле типа password, хранится только на
   сервере и не отдаётся в браузер).
4. Нажмите **Сохранить**.

Без ключа TonAPI тоже работает, но с жёстким лимитом запросов (~1 rps), чего
может не хватить при наплыве покупателей. Тарифы/лимиты — на
https://tonconsole.com/tonapi (free, plus, advanced).

Официальная документация:
- TonConsole / TonAPI: https://docs.tonconsole.com/tonapi
- TonAPI REST (метод событий счёта): https://docs.tonapi.io
- TON Docs (обзоры API): https://docs.ton.org

Проверка, что ключ рабочий (выполнять на сервере, где крутится приложение):

```bash
curl -H "Authorization: Bearer <ВАШ_КЛЮЧ>" \
  "https://tonapi.io/v2/blockchain/accounts/<ВАШ_АДРЕС_UQ...>/events?limit=5"
```

Ответ `200` со списком событий — ключ ок.

### Как TON-платёж проверяется (архитектура)

```
Mini App ──💎 Купить──▶ POST /api/payments/ton/create
                            создаёт payment id, считает сумму в nanoTON,
                            возвращает адрес + точную сумму + комментарий
                                  │
        TonConnect: покупатель подключает кошелёк, видит сумму,
        отправляет перевод НА ВАШ адрес С КОММЕНТАРИЕМ = payment id
                                  │
   Mini App поллит POST /api/payments/ton/verify
       → сервер: GET https://tonapi.io/v2/blockchain/accounts/<адрес>/events
         ищет событие TonTransfer на ваш адрес, где comment содержит payment id
         и сумма ≥ ожидаемой (цена пакета × ton_per_rub)
                                  │
          нашли → пометили paid → начислили кредиты (ровно один раз)
```

Тонкости:

- Это **некастодиальный** приём: деньги приходят сразу в ваш кошелёк, ничего
  промежуточного нет. Поэтому возврат, если он нужен, вы делаете сами
  обычным переводом из своего кошелька.
- Покупатель должен покрыть и сетевую комиссию перевода — учитывайте это при
  выставлении сумм (перевод «с комментарием» стоит комиссию сети, обычно
  доли TON).
- Верификация идёт по событиям счёта через TonAPI; комментарий — это наш
  `payment id`, поэтому посторонние переводы на ваш адрес ничего не начисляют.
- Безопасность: ключ TonAPI читает события **вашего** адреса — никого не
  «подключает» и ничего не подписывает. Не передавайте его никому.

### Курс «TON за 1 ₽»

Формула: `ton_per_rub = 1 / (цена 1 TON в рублях)`.

Примеры: цена TON ≈ 100 ₽ → `0.01`; цена ≈ 150 ₽ → `0.0067`; цена ≈ 60 ₽ →
`0.0167`. Цена пакета «Старт» (490 ₽): `490 × ton_per_rub` TON.

Проверяйте актуальный курс на бирже (например, https://coinmarketcap.com/currencies/toncoin/)
и обновляйте в админке. По умолчанию стоит `0.01` (= 1 TON за 100 ₽).

## 3. Почему «+2 генерации» не уменьшались (важно!)

Это не ошибка списания, а **тестовый режим**:

- По умолчанию в настройках включён параметр «бесконечные генерации (тест)»
  (`test_unlimited = 1`), а он действует для **администратора**. Вы тестируете
  под своим админ-аккаунтом — поэтому генерации ничего не списывают.
- Плюс у каждого аккаунта первая генерация всегда бесплатная (пробная), и
  только со второй начинают тратиться кредиты.

Что сделать для проверки реального списания:
**/admin → Настройки → выключите «Бесконечные генерации (тест)»** (значение
`0`) → Сохранить. После этого каждая генерация (кроме первой пробной) будет
уменьшать счётчик кредитов на 1.

Для обычных пользователей (не админов) списание работает всегда и не зависит
от этого тумблера.

## 4. Бонус «+1 за подписку» — теперь с реальной проверкой

Раньше в боте при недоступной проверке бонус выдавался «в демо-режиме», а для
VK проверки не было вовсе — поэтому вы получили +1 и +1, даже не открыв ссылку
VK. Это исправлено (fail-closed):

- **Telegram**: «Забрать бонус» вызывает `getChatMember` (бот должен быть
  **администратором канала**, в админке заполнен `telegram_channel_id` и ссылка
  `channel_telegram_url`). Нет подписки → отказ с кнопкой «Подписаться» и
  повторной кнопкой «Забрать бонус». Нельзя проверить (канал не задан / бот не
  админ) → честный отказ с подсказкой владельцу.
- **VK**: та же схема через `groups.isMember` (нужны `vk_group_id` и
  `vk_access_token`, которые уже используются для VK-бота). Если токен не
  позволяет проверку — бонус не выдаётся.
- **Сайт / Mini App** (`POST /api/rewards/verify`): проверка идёт только по
  профилю, **привязанному к аккаунту** (сервер берёт `user.telegramId` /
  `user.vkId`, а не id, присланный с клиента). Не привязан профиль → подсказка
  привязать или забрать бонус в боте.

### Чек-лист проверки бонуса

1. Канал: `@ваш_канал` (или `-100…`) в админке → **Боты**, ссылка на канал —
   там же. Бота добавьте администратором канала.
2. VK: группа и токен уже настроены для бота сообщества.
3. Откройте бота → «🎁 Бонусы» → подпишитесь → «Забрать бонус» → `+1`.
4. Повторное нажатие → «Этот бонус уже получен».

## 5. Проверка «из коробки» (контрольный список)

- [ ] В админке → Боты подключён Telegram-бот и настроен вебхук.
- [ ] В админке → Настройки: вписан `ton_address`, ключ TonAPI, адрес
      `https://tonapi.io`, курс `ton_per_rub`.
- [ ] `curl` с ключом TonAPI возвращает события по вашему адресу.
- [ ] В «Звёзд за 1 ₽» стоит нужный курс (например `1`).
- [ ] Открыт Mini App внутри Telegram → вкладка «💎 Тарифы» → «⭐ Звёздами» —
      открывается нативный чек.
- [ ] Для TON: «💎 TON» → подключить кошелёк → перевод с комментарием —
      через ~10–40 с кредиты начислены.
- [ ] Для проверки списаний: `test_unlimited = 0` в админке.
- [ ] Бонусы за подписку выдаются только после реальной проверки (см. §4).

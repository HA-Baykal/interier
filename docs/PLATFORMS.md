# Общий продукт: сайт, Android/iPhone и Telegram/VK/MAX

Рабочая ветка: `arena/01a070c8-interier`. Не открывать PR и не сливать до отдельного разрешения владельца.

## Решение владельца от 2026-09-06

1. Сначала дать администратору тестировать разные модели и сравнивать качество/расходы.
2. Не выбирать модель платной подписки автоматически: владелец сообщит результат тестов.
3. Сохранить запрос на бесплатный первый просмотр в минимальном качестве и лучшее качество за пакет, но окончательные тарифы/пробный лимит определить после тестов. Ответы на предложенный опрос не получены — не считать их согласованными.
4. Добавить крупный просмотр и перетаскиваемое «До / После»: слева исходное фото, справа результат, по умолчанию 50/50. Это не ИИ-апскейл и не платный вызов.
5. Нужны настоящие клиенты Android и iPhone и боты Telegram, VK, MAX с общей бизнес-логикой.

## Текущий этап: тестовая панель и просмотр

- В админке отдельная панель: GPT Image 2 Low/Medium/High, Nano Banana, Nano Banana Pro 2K.
- Каждый запуск — один запрос, один стиль. Тестовый профиль защищён проверкой администратора на сервере.
- Профили не меняют общую модель/режим, тарифы или правила для обычных пользователей.
- Для каждой модели собственный шаблон API. У Nano отключён дополнительный платный перевод; используются JPEG/PNG.
- Публичные цены показаны как **оценки**, не как фактическое списание. Для точного расхода владелец смотрит GenAPI.
- В истории сохраняются профиль, параметры, оценка и время обработки; сумма оценки не используется как денежная проводка.
- Готовые изображения просматриваются с ползунком, увеличением и перемещением. Просмотр не запускает ИИ.
- Новые модели ещё должны пройти реальные тесты владельца. Успех тестов с имитированным API не доказывает качество моделей.

## Что ещё НЕ готово

- Подключение реальной покупки/подписки и проверка платежей. В текущем сайте пакеты — витрина, кнопки оплаты выключены. Купленные и бонусные кредиты пока не имеют раздельного происхождения.
- Android APK/AAB, iOS/TestFlight/App Store. Мобильного клиента ещё нет; не выдавать адаптивный сайт или PWA за готовые магазинные приложения.
- Подключённые Telegram/VK/MAX-боты. Вебхуки, аккаунты ботов и их авторизация ещё не настроены.
- Автоматическая связка Low + ИИ-апскейл. Владелец её пока не утвердил; крупный просмотр не заменяет улучшение файла.

## Целевая архитектура — без трёх копий генерации

```text
Сайт Next.js ─────────────────────────────┐
Android + iPhone (один клиент Expo/RN) ───┼─ общий защищённый API
Telegram / VK / MAX (тонкие адаптеры) ───┘       │
                                         единые аккаунты / баланс
                                         стили / каталог моделей
                                         очередь заданий / история
                                         GenAPI / Redis / Blob
```

`src/lib/generation/model-catalog.ts` и геометрия просмотра не содержат серверных ключей и могут переиспользоваться клиентами. Генерация, ключ GenAPI, биллинг и операции с облачными хранилищами остаются только на сервере. Мобильный интерфейс общий для Android/iOS; интерфейсы API мессенджеров различаются, поэтому адаптеры платформ всё равно нужны.

## Последовательность следующих этапов

1. **Выделить общий сервис заданий.** Нынешний `/api/generate` ожидает результат в HTTP-запросе. Для ботов нужен быстрый приём события и надёжная очередь: повтор вебхука не должен создавать второй платный запрос. Хранить состояние задания, ID запроса провайдера, идемпотентность и результат в постоянном хранилище.
2. **Единая идентификация.** Защищённое связывание веб-/мобильного аккаунта с Telegram/VK/MAX одноразовым кодом. Нельзя объединять пользователей по имени или просто доверять присланному `userId`. Бот-токены не подменяют пользовательскую авторизацию.
3. **Адаптеры трёх ботов.** Проверять секрет/подпись и источник платформы до обработки события. Один общий сценарий загрузки фото, выбора стиля, проверки лимита, создания задания и доставки результата. Реальное подключение требует аккаунтов ботов и секретов, вводимых владельцем в настройки хостинга, не в чат и не в Git.
4. **Клиент Expo/React Native.** Вход, съёмка/выбор фото, стили, задания и история используют общий API. Токен пользователя — в защищённом хранилище устройства; ключ GenAPI никогда не включать в приложение.
5. **Платежи и публикация.** Уточнить правила оплаты цифровых функций для выбранных магазинов/мессенджеров, проверять подтверждения оплаты на сервере. Для магазинных сборок нужны аккаунты разработчика и подпись. Код приложения, рабочая сборка и опубликованное приложение — разные результаты, сообщать статус честно.

## До публичного API для приложений и ботов

- Preview сейчас защищён авторизацией Vercel. Он не является готовым публичным API для нативного клиента/вебхуков.
- Не вшивать токен обхода защиты Vercel в мобильный клиент и не снимать защиту до серверных лимитов/авторизации.
- Ограничить тестовый безлимит администраторами, утвердить бесплатный лимит, добавить защиту регистрации/запросов от злоупотреблений и повторного списания.
- Согласовать правила качества для пробника, купленных и бонусных кредитов. Сейчас эти правила сознательно не меняются.
- Продумать удаление аккаунта/фото, политику конфиденциальности и согласие на передачу фото ИИ-провайдеру. Public Blob означает доступность по точной ссылке, а не приватное хранилище.

## Уточнение владельца: общая модель и подтверждённая регистрация

- Общая модель сайта по умолчанию — GPT Image 2 Low.
- В админке нужен явный выбор общей модели/качества с применением для всех новых генераций. Изолированные тесты остаются отдельно.
- Требуются подтверждение почты и вход через Telegram/VK/MAX; неподтверждённые данные не должны давать доступ к расходованию баланса.
- Одного подтверждения недостаточно: нужны лимиты, защита от массовых регистраций, от повторного начисления реферальных бонусов и повторного запуска бесплатных генераций.
- Реальные социальные провайдеры, отправитель писем, стабильный адрес и секреты подключения ещё не настроены. Не обозначать вход через мессенджеры как готовый до проверки настоящих подтверждений.


## Защитный промежуточный этап

- Неподтверждённым обычным аккаунтам запрещён запуск генерации на сервере до загрузки фото и платного вызова.
- Существующий администратор продолжает работать; тестовый безлимит больше не распространяется на обычных пользователей.
- Поля Telegram/VK, имена и ранее выданные бонусы не считаются подтверждением личности.
- Реферальное вознаграждение за непроверенный адрес откладывается. Связь с пригласившим хранится как pending, старые начисления не отбираются.
- Симулированная проверка подписок отключена: endpoint не выдаёт кредиты за произвольный username/externalId.
- Новые аккаунты пока могут зарегистрироваться как **неподтверждённые**, но не могут тратить баланс. Это защитный барьер, а не законченная система подтверждения.
- Владелец сообщил: ботов и отправляющей почты пока нет, всё создаётся с нуля. Реальные подтверждения почты/Telegram/VK/MAX, rate limits, CAPTCHA и общий бюджет бесплатных попыток ещё нужно подключить до публичного запуска. До этого не снимать защиту Preview.


## Telegram: текущий реализованный этап

Добавлен настоящий протокол подтверждения через `@interier_home_bot`: одноразовый запрос сайта,
кнопка согласия в приватном чате, защищённый webhook и выдача/привязка общей сессии. Код и
автотесты готовы; **живая проверка ещё ожидается** после настройки Vercel и подключения webhook.
Новый социальный аккаунт не получает выдуманный email, не становится администратором и не
объединяется автоматически с чужим аккаунтом. Повторный вход не сбрасывает пробный лимит.

Настройка: [TELEGRAM-LOGIN.md](TELEGRAM-LOGIN.md). Нужен серверный токен (владелец уже добавил
его в Preview), для защищённого Preview — автоматический bypass-secret Vercel и Redeploy.
Клиентам этот секрет не выдаётся. Кнопка подключения не вызывается автоматически на деплое.

Также реализованы отдельные Redis TTL-записи входа/rate limits и общий лимит 10 бесплатных
изображений за 24 часа (настраивается администратором, ошибки старта тоже учитываются).
Это не полная антифрод-система и не денежная гарантия расхода: при смене модели цена меняется.

**Остаются:** реальная проверка Telegram владельцем, email-коды, VK/MAX, CAPTCHA/публичный запуск,
платежи, генерация прямо в трёх ботах с общей очередью и мобильные сборки Android/iOS.

# Подтверждённый вход через @interier_home_bot

## Статус

Реализованы сервер, интерфейс, защита webhook, одноразовые запросы входа/привязки и тесты. Реальное подключение требует настроек Vercel и проверки владельцем в Telegram. Сам факт сборки/успеха fixture-тестов не означает, что живой webhook уже подключён.

Этот бот пока **только подтверждает вход**. Генерация фото из переписки, VK/MAX, email-коды и мобильные магазинные приложения — отдельные незавершённые этапы.

## Что уже сделал владелец

- Создал `@interier_home_bot`.
- Сохранил `TELEGRAM_BOT_TOKEN` в окружении **Preview** (значение не передавалось в чат).

## Настройки сервера

- `TELEGRAM_BOT_TOKEN`: токен только в серверном окружении.
- `TELEGRAM_BOT_USERNAME`: необязательно; по умолчанию `interier_home_bot`.
- `AUTH_PUBLIC_URL`: необязательный постоянный HTTPS-адрес без пути/параметров. По умолчанию используется системный `VERCEL_BRANCH_URL`, а не одноразовый URL деплоя.
- Для защищённого Preview: **Settings → Deployment Protection → Protection Bypass for Automation → создать secret**. Vercel сам добавляет `VERCEL_AUTOMATION_BYPASS_SECRET`. После создания/смены нужен Redeploy этой ветки. Общую защиту сайта отключать не требуется.

Секрет обхода используется только на сервере при регистрации URL webhook у Telegram. Он не передаётся в HTML, мобильное приложение, публичную диагностику или ссылки входа. Не копировать его в чат. Сам webhook дополнительно требует отдельный `X-Telegram-Bot-Api-Secret-Token`, который сервер безопасно выводит из токена бота и пространства данных этой ветки.

### Если Vercel требует Secret ровно из 32 символов

`telegram-webhook` — только возможная заметка **Note**, а не секрет. Не дописывайте это
название до 32 символов и не используйте токен BotFather: нужен новый случайный ключ.
В `/admin#telegram-setup` есть кнопка **«Создать и скопировать ключ для Vercel»**.
Она использует Web Crypto в браузере владельца (16 случайных байтов → 32 hex-символа),
не делает сетевых запросов и не сохраняет значение на сервере, в localStorage или в Git.

Вставьте результат в поле **Secret**, а Note оставьте пустым. Создание секрета на сайте
само по себе не регистрирует его в Vercel — после вставки подтвердите Add Secret и
назначьте запись системной переменной `VERCEL_AUTOMATION_BYPASS_SECRET`, если потребуется.
Не присылайте значение в переписку или скриншот раскрытого поля.

Справка Vercel: https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation
Справка Telegram: https://core.telegram.org/bots/api#setwebhook

## Подключение после Redeploy

1. Войти обычным паролем администратора на **новый** Preview.
2. Открыть `/admin#telegram-setup`.
3. Нажать «Подключить бота к этой версии».
4. Сервер проверит `getMe`, имя бота, текущий webhook и доступность своего endpoint. Только затем вызывает `setWebhook`.
5. Если бот уже подключён к другому адресу, сервер откажется без явного подтверждения переключения. Один бот имеет один webhook. Подключение **не выполняется автоматически** при старте/деплое и не удаляет ожидающие обновления.

## Сначала привязать Telegram к существующему администратору

Чтобы сохранить **тот же** аккаунт, баланс и историю:

1. Не выходить из текущего аккаунта администратора. Открыть `/account`.
2. Нажать «Подтвердить привязку Telegram».
3. Открыть бота по показанной ссылке. Сравнить шестизначный код на сайте и в сообщении.
4. Нажать «Подтвердить» только если вы сами начали действие и код совпадает.
5. Вернуться на сайт и дождаться сообщения об успешной привязке.
6. Затем можно выйти и проверить кнопку «Войти через Telegram».

Если сначала войти через Telegram анонимно, будет создан **новый обычный** аккаунт, не администратор. Автоматического объединения по имени, непроверенному email или старому полю `telegramId` нет. Конфликт привязки не объединяет балансы.

Новый Telegram-аккаунт имеет `email: null`, а не выдуманный адрес. Парольный вход для него недоступен. Подтверждённый ID хранится отдельно от прежних непроверенных социальных полей. Повторный вход возвращает тот же аккаунт и не восстанавливает потраченную пробную попытку/кредиты.

## Как защищён вход

- Случайный ID запроса и отдельный 256-битный секрет браузера. В ссылку боту попадает только ID.
- Срок жизни — 10 минут. Код в интерфейсе нужен для сравнения, сам по себе он не является паролем.
- Webhook проверяет секрет **до** чтения данных и работы с аккаунтами.
- Подтверждения принимаются только от того же пользователя в приватном чате. Имена и произвольные ID с сайта не являются доказательством.
- На старте бот показывает предупреждение против подтверждения чужой ссылки.
- Временные запросы и rate-limit counters хранятся в отдельных TTL-ключах Redis, не в большом документе истории. На Vercel нет fallback в память при ошибке Redis. Локальный fallback — только для разработки.
- Выдача аккаунта/сессии идемпотентна: повтор webhook/опроса не создаёт вторую пробу. Завершённая и затем закрытая сессия не возрождается повтором опроса.
- Привязка требует действующей подтверждённой сессии сайта. Начатое завершение входа нельзя отменить задним числом; после входа можно выйти.
- Авторизация не выдаёт бонусные/реферальные кредиты. Приглашение может сохраняться как pending, пока бонусная программа не подключена к реальным проверкам.

Это подтверждает владение аккаунтом Telegram, а **не уникальность физического лица**. Несколько настоящих Telegram-аккаунтов всё ещё возможны; перед публичной рекламой нужны дополнительные антифрод-настройки/CAPTCHA и наблюдение.

## Ограничение расходов

- Для обычного пользователя — до 3 попыток генерации в минуту.
- По умолчанию — **10 бесплатных изображений на весь сервис за скользящие 24 часа**. Меняется в админке. Ноль отключает бесплатные попытки.
- Считаются изображения, а не кнопки: набор из шести стилей занимает шесть мест.
- Неудачные старты тоже занимают место в общем лимите: внешнее списание могло уже произойти. Личная проба при полном сбое может возвращаться, но общий защитный бюджет — нет.
- Это лимит количества, не гарантия суммы в рублях: стоимость зависит от выбранной модели.
- Администраторские тесты не расходуют этот бесплатный лимит и остаются платными у GenAPI.

## Проверки

`npm test` проверяет корректное/чужое/повторное подтверждение, истечение, отмену, привязку, отсутствие автоматического слияния, переиспользование аккаунта, конфликты, секреты и отдельные Redis TTL/CAS ключи. `npm run test:browser` проверяет клиентский сценарий на имитированных Telegram-ответах без обращения к реальному боту. Финальная живая проверка выполняется владельцем после настройки webhook.

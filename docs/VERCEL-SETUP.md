# Подключение Vercel и проверка без PR / merge

Рабочая ветка этой сессии: **`arena/01a070c8-interier`**.
Проверяем её **Preview-деплой на настоящем Vercel**, не старый сайт с `main`.
PR, merge и продвижение в Production — только после отдельного подтверждения владельца.

## 1. Откройте нужный проект

1. Зайдите в Vercel и откройте проект **interier**.
2. В **Deployments** найдите ветку `arena/01a070c8-interier`.
3. Убедитесь, что у последнего коммита статус **Ready**. Позже откроем его через **Visit**.
4. Production Branch менять не надо. Preview — полноценный работающий сайт, а не локальная имитация.

Если Vercel показывает собственный экран входа, это **Deployment Protection**, а не ошибка входа в Interier.
Войдите в свой Vercel-аккаунт и откройте Preview в отдельной вкладке. Отключать защиту ради проверки не требуется.

## 2. Подключите Upstash Redis — аккаунты, сессии, история и настройки

1. В проекте откройте **Storage → Create Database** (в некоторых версиях панели — **Connect Store** / **Marketplace**).
2. Выберите **Upstash → Redis**. Не Vector, не QStash и не Redis по обычному TCP URL.
3. Если интеграции ещё нет, установите её. Можно создать управляемый Vercel аккаунт Upstash либо связать существующий.
4. Создайте базу, например `interier-redis`. Регион желательно выбрать рядом с регионом Vercel Functions.
5. Проверьте выбранный тариф и его лимиты, прежде чем подтверждать создание.
6. В **Connect to Project** выберите **interier**, окружения **Preview** и **Production**.
7. В **Settings → Environment Variables** проекта проверьте наличие пары:

   ```text
   UPSTASH_REDIS_REST_URL
   UPSTASH_REDIS_REST_TOKEN
   ```

   Если интеграция создала `KV_REST_API_URL` + `KV_REST_API_TOKEN`, они тоже поддерживаются.
   **Нужна полная пара от одной базы.** Нельзя смешивать URL Upstash с токеном другой KV-базы.
   `REDIS_URL`, `KV_URL` и `KV_REST_API_READ_ONLY_TOKEN` эту пару не заменяют.

8. Если автоматического добавления нет: откройте базу в Upstash → **REST API**,
   скопируйте **REST URL** и **read/write token** прямо в Environment Variables Vercel.
   Не присылайте их в чат и не добавляйте в Git.

### Изоляция тестирования

Можно подключить один Redis к обоим окружениям: приложение разделяет документы автоматически.

- Production: прежний ключ `app:db` — существующие данные не переносятся и не сбрасываются.
- Preview: `app:preview:<ветка-с-хешем>:db` — стабильный между redeploy одной ветки.
- Аккаунты и сохранённый в админке ключ ИИ в Preview и Production **отдельные**. Это не потеря данных.
- **Не задавайте `REDIS_DB_KEY=app:db` для Preview.** Это отключит изоляцию от Production.
- Для дополнительной изоляции можно создать отдельные базы Redis для двух окружений.

## 3. Подключите Vercel Blob — исходные фото и результаты

1. В **Storage → Create Database → Blob** нажмите **Continue**.
2. Выберите доступ **Public**. Текущий коннектор сохраняет публичные URL и не обслуживает Private Blob.
3. Назовите хранилище, например `interier-photos`, выберите регион и создайте его.
4. Подключите к проекту **interier**, окружения **Preview** и **Production**.
5. Оставьте стандартные имена переменных. При современном подключении в Environment Variables появятся:

   ```text
   BLOB_STORE_ID
   BLOB_WEBHOOK_PUBLIC_KEY
   ```

   **Это нормальное подключение. Создавать `BLOB_READ_WRITE_TOKEN` дополнительно не нужно.**
   Приложение использует `BLOB_STORE_ID`, а Vercel SDK сам получает и обновляет временные
   OIDC-учётные данные из окружения / контекста запроса. `VERCEL_OIDC_TOKEN` не нужно
   создавать вручную, копировать или пересылать. `BLOB_WEBHOOK_PUBLIC_KEY` — ключ проверки
   webhook-подписей, не токен для загрузки фото.

6. Если уже используется старый способ с `BLOB_READ_WRITE_TOKEN`, он тоже поддерживается.
   Если указаны оба варианта, явный read/write token сохраняет прежний приоритет.
   Для локальной разработки можно использовать read/write token либо `vercel env pull`
   с подключённым Blob store и управляемыми OIDC-учётными данными.
7. Убедитесь, что подключение / переменные доступны **Preview**, а не только Production.
   Само наличие `BLOB_STORE_ID` показывает настройку, но запись проверяется отдельно кнопкой диагностики.

В Blob сохраняются **обе** картинки: оригинал и скачанный у GenAPI результат.
Временная ссылка провайдера не используется как постоянное хранилище.
Preview пишет в свой подкаталог `uploads/preview/...`, Production — в `uploads/`.

> **Приватность:** Public Blob доступен любому, у кого есть точная ссылка.
> «Не опубликовано в галерее» означает отсутствие в публичном списке, а не авторизацию на скачивание файла.
> Пока не реализовано закрытое хранилище с проверкой владельца, не загружайте конфиденциальные фотографии.

## 4. Проверьте переменные приложения

В **Settings → Environment Variables** добавьте значения для **Preview**.
При необходимости сразу задайте те же переменные для Production, но это не обновит код на `main`.

Если четыре `COMPATIBLE_*` уже есть, но под ними написано только **Production**,
новые секреты создавать не надо: у каждой строки откройте **⋯ → Edit**, в **Environments**
добавьте галочку **Preview**, оставьте **Production** включённым и нажмите **Save**.
Значения не меняйте и не раскрывайте. Затем выполните Redeploy **ветки сессии**.


| Переменная | Значение |
| --- | --- |
| `ADMIN_EMAIL` | Ваш email для админ-аккаунта |
| `ADMIN_PASSWORD` | Новый длинный уникальный пароль — не `admin123` |
| `GENERATION_MODE` | `compatible` |
| `COMPATIBLE_PROVIDER` | `genapi` |
| `COMPATIBLE_BASE_URL` | `https://api.gen-api.ru` |
| `COMPATIBLE_MODEL` | `gpt-image-2` |
| `COMPATIBLE_API_KEY` | API-ключ GenAPI, **либо** сохраните его позже в админке |

Вставляйте только значение, без `ИМЯ_ПЕРЕМЕННОЙ=`, кавычек и обратных кавычек.
Все токены и пароли — **серверные**, без префикса `NEXT_PUBLIC_`.
Сохранённый в админке ключ имеет приоритет над ключом из окружения; пустое поле в админке означает «не менять ключ».
Новый ключ автоматически включает `compatible`. Явно выбрать демо обратно можно отдельным сохранением без нового ключа.

**Не включайте платный API с общеизвестным паролем администратора.**
Существующий `test_unlimited=1` разрешает пользователям неограниченные генерации за ваш баланс GenAPI:
для закрытой проверки оставьте Deployment Protection, перед публичным запуском отключите безлимит в админке.

## 5. Лимит времени функции

В **Settings → Functions** проверьте **Fluid Compute** и доступный лимит выполнения.
Для `/api/generate` код задаёт `maxDuration = 300` (5 минут), runtime — Node.js.
На конфигурации с более коротким жёстким лимитом один экспорт не даст функции больше времени:
потребуется включить Fluid Compute / подходящую конфигурацию тарифа.
Опрос ИИ и сетевые запросы ограничены по времени; все стили обрабатываются параллельно.

## 6. Обязательно выполните Redeploy

1. Откройте **Deployments**, отфильтруйте ветку `arena/01a070c8-interier`.
2. У **последнего** её деплоя нажмите **⋯ → Redeploy**.
3. Дождитесь **Ready**, откройте **Visit** в отдельной вкладке.
4. Проверьте, что это Preview новой ветки, а не Production со старым `main`.

Добавленные переменные **не применяются к уже работающему старому деплою** без redeploy.

## 7. Проверьте подключение до платной генерации

На **том же домене Preview** откройте `/api/admin/bootstrap`.

Ожидаем:

```json
{
  "ok": true,
  "storage": "redis",
  "uploads": "blob",
  "blobAuthentication": "oidc",
  "configuredAccountExists": true,
  "configuredAccountIsAdmin": true,
  "ephemeralStorage": false,
  "missingEnvironment": [],
  "environment": "preview"
}
```

`blobAuthentication` — `oidc` для `BLOB_STORE_ID` или `token` для старого read/write token.
`databaseKey` должен содержать `preview`, `commit` — SHA проверяемой версии.
`credentialsFromEnv: true` означает, что логин/пароль берутся из ваших ADMIN-переменных.

Затем:

1. Откройте `/login`, войдите под `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
2. Откройте `/admin`. Если ключ ИИ не задан через окружение, вставьте его и нажмите **Сохранить**.
3. Нажмите **Проверить ИИ и хранилища**.
4. Та же диагностика доступна администратору через `/api/admin/genstatus?probe=1`.

Ожидаем:

- `mode: "compatible"`, `aiConfigured: true`, `keyConfigured: true`;
- `probe.ok: true`, `probe.keyAccepted: true`, `probe.hasBalance: true`;
- `storageChecks.database.ok: true`;
- `storageChecks.uploads.ok: true`, `storageChecks.uploads.cleanup: true`.

Проверка ключа делает только `GET /api/v1/user` — **платная генерация не запускается**.
Проверка хранилищ создаёт, читает и удаляет отдельный временный ключ Redis и маленький тестовый PNG в Blob.
Это обычные операции хранилищ, учитываемые в их лимитах; реальные данные не сбрасываются.
Сам API-ключ, токены Redis/Blob, пароль, email и точный баланс из аккаунта GenAPI в диагностике не возвращаются.
Успешная проверка ключа ещё **не доказывает**, что выбранная модель выполнит генерацию.

Проверка API ждёт до **30 секунд суммарно** и допускает только одну повторную попытку
при сбое соединения или HTTP 5xx. Это повтор read-only GET, **не платной генерации**.
`keyAccepted: null` означает «не удалось проверить», а не «неверный ключ».
Только фактический HTTP 401/403 даёт `keyAccepted: false`.
При сетевом сбое отчёт содержит `code`, безопасный `networkCode` (если доступен),
`attempts`, `elapsedMs` и регион Vercel в `deployment.region`.
Если повторяется таймаут, передайте этот отчёт: заменять ключ наугад не нужно.
Старый отчёт убирается при повторной проверке; дождитесь завершения кнопки.

## 8. Проверка фото и сохранности аккаунта

1. Загрузите неконфиденциальное фото комнаты и выберите **один** стиль для первой проверки.
2. Запустите генерацию, дождитесь результата. Проверьте, что это редизайн, а не исходник с цветовым фильтром.
3. При ошибке скопируйте её текст. Не запускайте много повторов: реальные запросы расходуют баланс GenAPI.
4. У оригинала и результата должны быть адреса `*.public.blob.vercel-storage.com`, не `/api/uploads/...` и не временный адрес GenAPI.
5. Перезагрузите страницу и проверьте историю / личный кабинет.
6. Зарегистрируйте отдельного тестового пользователя и выйдите из него.
7. Сделайте ещё один Redeploy **этой же ветки**. На новом домене может понадобиться войти заново:
   cookie привязана к домену, но тот же аккаунт и история должны сохраниться в Redis.
8. Если всё работает, сообщите об этом в этой сессии. PR всё равно оформляется только по отдельной явной команде.

## Если что-то не получилось

| Симптом | Проверка |
| --- | --- |
| `storage: memory` / `database_not_configured` | REST URL + read/write token, окружение Preview, затем Redeploy |
| `uploads: unconfigured` / `blob_not_configured` | `BLOB_STORE_ID` (или старый `BLOB_READ_WRITE_TOKEN`) именно в Preview, Public Blob, затем Redeploy |
| Старый деплой требует `BLOB_READ_WRITE_TOKEN`, хотя есть `BLOB_STORE_ID` | Откройте последний деплой ветки с поддержкой OIDC, не старую ссылку |
| OIDC environment / credentials error | Blob → Projects → подключение к правильному проекту и Preview. Временный токен вручную не вставляйте |
| Redis 401/403 | Неверный / read-only токен либо URL от другой базы. Не сбрасывайте базу |
| Blob access / store error | Токен от правильного store, Public access, тариф/лимиты |
| `probe.code: timeout` / `network_error`, `keyAccepted: null` | HTTP-ответ не получен или чтение ответа прервано. Ключ не признан неверным. Передайте безопасный отчёт с `networkCode`, `elapsedMs` и регионом; не меняйте ключ наугад |
| GenAPI 401/403 | Проверьте действительность и права ключа, ограничения доступа у GenAPI. Не пересылайте ключ в чат |
| GenAPI 402 / `hasBalance: false` | Проверьте баланс GenAPI |
| GenAPI 422 | Модель и её входные параметры; передайте полный безопасный текст ошибки |
| 504 / function timeout | Deployment → Functions / Runtime Logs; Fluid Compute, лимит 300 секунд |
| В диагностике 403 | Войдите администратором на этом же домене; либо используйте кнопку в `/admin` |
| После настройки всё ещё старый баннер | Открыт старый Production-деплой или не выполнен Redeploy ветки |

**Не нажимайте «сброс демо» для лечения подключения:** это удаляет данные выбранной базы.
Подключение Redis/Blob не восстанавливает фото и аккаунты, которые уже исчезли из памяти старой функции.
Данные локального `data/app.json` автоматически в Redis не импортируются; если есть ценные локальные данные,
сначала сохраните резервную копию и согласуйте отдельный перенос.

Для продолжения достаточно ссылки на проверяемый Preview и безопасного вывода двух диагностических эндпоинтов.
Секреты не нужны.
